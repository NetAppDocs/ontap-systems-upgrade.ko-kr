:nofooter:

[role="lead"]
ARL을 사용하여 노드를 업그레이드하기 전에 절차가 어떻게 작동하는지 이해해야 합니다. 이 문서에서는 여러 단계로 절차를 세분화하여 설명합니다.



[[upgrade-the-node-pair]]
== 노드 쌍을 업그레이드합니다

노드 쌍을 업그레이드하려면 기존 노드를 준비하고 기존 노드와 새 노드 모두에서 업그레이드 단계를 따릅니다. 그런 다음 기존 노드를 사용 중지합니다.



[[arl-upgrade-sequence-overview]]
== ARL 업그레이드 시퀀스 개요

기존 컨트롤러 하드웨어를 교체용 컨트롤러 하드웨어로 HA 페어 구성을 활용하여 루트가 아닌 어그리게이트의 소유권을 재배치하는 방식으로 한 번에 하나의 컨트롤러씩 업그레이드합니다. 올바른 업그레이드 노드에 도달하려면 모든 루트가 아닌 어그리게이트의 소유권을 두 번 재배치해야 합니다.

각 집합에는 홈 소유자와 현재 소유자가 있습니다. 홈 소유자는 애그리게이트의 실제 소유자이며 현재 소유자는 임시 소유자입니다.

다음 그림에서는 절차의 단계를 보여 줍니다. 굵고 연한 회색 화살표는 애그리게이트의 재배치와 LIF의 이동을 나타내고, 더 얇은 검은색 화살표는 원래 노드의 제거를 나타냅니다. 더 작은 컨트롤러 이미지는 원래 노드를 나타내고 더 큰 컨트롤러 이미지는 새 노드를 나타냅니다.

image:arl_upgrade_manual_image1.PNG["ARL 절차의 단계를 보여 주는 그림"]

각 단계에서 수행하는 주요 작업과 단계 종료 시 애그리게이트 소유권 상태에 대해 알아보십시오. 자세한 단계는 절차 뒷부분에 제공됩니다.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-1.png["1개"]link:determine_aggregates_on_internal_drives.html["1단계: 업그레이드 준비"]
[role="quick-margin-para"]
1단계 동안 필요한 경우 내부 디스크 드라이브에 루트 애그리게이트 또는 데이터 애그리게이트가 포함되지 않았는지 확인하고, 업그레이드를 위해 노드를 준비하고, 일련의 사전 점검을 실행합니다. 필요한 경우 Storage Encryption 디스크를 다시 입력하다 새 컨트롤러를 netboot에 준비합니다.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-2.png["2개"]link:relocate_non_root_aggr_node1_node2.html["2단계: 노드1을 폐기합니다"]
[role="quick-margin-para"]
2단계에서는 비루트 애그리게이트를 노드 1에서 노드 2로 재배치하고, 장애가 발생하거나 거부된 애그리게이트를 포함하여 노드 1이 소유한 비 SAN 데이터 LIF를 노드 2로 이동합니다. 또한 프로시저에서 나중에 사용할 수 있도록 필요한 node1 정보를 기록하고 node1을 폐기합니다.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-3.png["세 가지"]link:install_boot_node3.html["3단계: 노드 3을 설치하고 부팅합니다"]
[role="quick-margin-para"]
3단계에서는 노드3을 설치하고 부팅한 다음 노드1에서 노드3으로 클러스터 및 노드 관리 포트를 매핑합니다. NetApp 볼륨 암호화(NVE)를 사용하는 경우 키 관리자 구성을 복원합니다. 그런 다음 노드1에 속한 데이터 LIF 및 SAN LIF를 노드2에서 노드3으로 이동하고, 모든 애그리게이트를 노드2에서 노드3으로 재배치한 다음, 노드2가 소유한 데이터 LIF 및 SAN LIF를 노드3으로 이동합니다.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-4.png["네"]link:record_node2_information.html["4단계: 노드2를 폐기합니다"]
[role="quick-margin-para"]
4단계에서는 나중에 사용할 수 있도록 필요한 노드 2 정보를 기록한 다음 노드 2를 폐기합니다.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-5.png["다섯"]link:install_boot_node4.html["5단계: 노드 4를 설치하고 부팅합니다"]
[role="quick-margin-para"]
5단계에서는 노드4를 설치하고 부팅한 다음 노드2에서 노드4로 클러스터 및 노드 관리 포트를 매핑합니다. NetApp 볼륨 암호화(NVE)를 사용하는 경우 키 관리자 구성을 복원합니다. 그런 다음 노드2에 속하는 데이터 LIF 및 SAN LIF를 노드3에서 노드4로 이동하고, 노드2의 애그리게이트를 노드3에서 노드4로 재배치한 다음, 노드2가 소유한 데이터 LIF 및 SAN LIF를 노드3으로 이동합니다.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-6.png["6개"]link:manage_authentication_kmip.html["6단계: 업그레이드를 완료합니다"]
[role="quick-margin-para"]
6단계에서는 새 노드가 올바르게 설정되었는지 확인하고, 새 노드가 암호화를 사용하는 경우 Storage Encryption 또는 NetApp Volume Encryption을 설정합니다. 또한 이전 노드의 사용을 중지하고 SnapMirror 작업을 다시 시작해야 합니다.
